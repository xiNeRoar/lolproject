## 非可妥協嘅技術規則

呢啲係工程規則，唔係設計建議。違反任何一條係 bug，唔係風格問題。

**1. 只用 generated hooks。**
所有 API calls 必須 import 自 `@workspace/api-client-react`。唔可以寫 `fetch("/api/...")` 或任何手寫 HTTP call。Hook 唔存在就喺 commit message 記錄需求（`// NEEDS_HOOK: description`），唔好自己寫。

**2. TypeScript strict。**
零 `any` casts，除非 OpenAPI schema genuinely 缺少某個 field。係嘅話加 `// TODO: add field to OpenAPI spec` comment 並且喺 commit message 列出。

**3. `useAuth()` hook 統一管理 auth state。**
創建 `src/hooks/use-auth.ts` 作為唯一 auth entry point：
```tsx
export function useAuth() {
  const id = localStorage.getItem("vclol_player_id");
  return { playerId: id ? Number(id) : null, isLoggedIn: !!id };
  // Phase 2: replace body with useGetAuthMe()
}
```
全 codebase 搜尋 `localStorage.getItem("vclol_player_id")`，全部換成 `useAuth()`。唯一例外係 `DevLogin.tsx`（set/remove action）同 `use-auth.ts` 本身。

**4. Query invalidation 用 generated key getters。**
```tsx
// 正確
import { getListTeamsQueryKey, getGetTeamQueryKey } from "@workspace/api-client-react";
queryClient.invalidateQueries({ queryKey: getListTeamsQueryKey() });

// 錯誤
queryClient.invalidateQueries({ queryKey: ["/api/teams"] });
```

**5. Mutation feedback 要一致。**
成功同失敗都用 `toast`（codebase 已有 sonner）。唔可以用 silent mutation。

**6. Shared utilities 抽取，唔好 copy-paste。**
以下 functions 喺現有 codebase 中有 duplication，必須抽做 shared file（位置由你決定）：
- ELO display helpers（`eloBadgeColor`、`rankLabel`、`rankIcon`）— 目前喺 Ladder.tsx、PlayerProfile.tsx、PlayerDashboard.tsx 各有一份
- Champion utilities（`CHAMP_IDS`、`toChampId`、`champPortraitUrl`）— 喺 PlayerProfile.tsx 同 PlayerDashboard.tsx 各有一份
- Badge metadata（`BADGE_META`）— 喺 PlayerProfile.tsx 同 PlayerDashboard.tsx 各有一份
- `EloDelta` display component — 喺 MatchDetail.tsx 同 PlayerProfile.tsx 各有一份

### NEW: `/teams` — Team Leaderboard

**用戶係誰：** 任何人，包括未登入嘅訪客。主要係想了解 community 競技水平嘅玩家。

**用戶想做咩：**
- 了解邊支 team 最強
- 知道自己嘅 team 係咩排名
- 決定去哪個 team 參加練習賽作為對手

**可用 data：**

```typescript
// useGetLadder() → LadderResponse
interface LadderResponse {
  season?: Season | null;    // 當前 season 資料，可能係 null
  entries: LadderEntry[];    // 排名列表，已按 teamElo 排序
}

interface LadderEntry {
  rank: number;       // 排名（1-based）
  id: number;         // team ID，用作 link 去 /teams/:id
  name: string;       // team 名稱
  tag: string;        // 2-5 字母 tag，e.g. "TSM"
  teamElo: number;    // 當前 ELO（base 1000）
  peakElo: number;    // 歷史最高 ELO
  wins: number;
  losses: number;
  winRate?: number;   // 0-100 的 percentage，可能 undefined
}

// useGetLadderSettings() → LadderSettings
interface LadderSettings {
  kFactor: number;              // ELO 計算用，喺 "How it works" 顯示
  minMatchesForDisplay: number; // 最少場次才上榜，喺 subtitle 顯示
  playoffSize: number;          // 前 N 名入 playoff，用作分隔線
  playoffFormat: string;        // "single_elimination" | "double_elimination"
  defaultMatchFormat: string;   // "BO1" | "BO3" | "BO5"
}
```

**Business rules（呢啲唔係設計決定，係 hard rules）：**
- `playoffSize` 決定分隔線位置：前 N 名係 playoff zone，視覺上要有明確區分
- `minMatchesForDisplay` 要喺頁面顯示，因為用戶可能搵唔到自己個 team（唔夠場次所以唔顯示）
- Season 資料如果有就顯示，連同剩餘日數（用 `season.endDate` 計算）
- `entries` 可能係空 array（platform 剛起步時）

**每個 entry 要顯示嘅資料：**

| 資料 | 用途 | 備註 |
|---|---|---|
| `rank` | 主要排名指標 | Top 3 可特別處理 |
| `name` + `tag` | 識別 team | tag 係簡短識別符，類似 Twitter handle |
| `teamElo` | 核心競技指標 | 最重要嘅數字，要最突出 |
| `peakElo` | 展示 team 歷史最佳表現 | secondary info |
| `wins` + `losses` | 勝負記錄 | |
| `winRate` | 勝率 | 可能 undefined，係的話唔顯示 |
| → link | Navigation | 整行可以 click 去 team profile |

**額外 context：**
- ELO 1000 係 base，所以 1000 以下係低，1200+ 係好，1400+ 係出色
- 現有 Ladder.tsx 有完整嘅參考實現，包括 season countdown、playoff divider 嘅 UX pattern，你可以直接參考或重用
- "How the Ladder Works" section 解釋規則，對新用戶重要，用 `ladderSettings` data

### NEW: `/teams/:id` — Team Profile

**用戶係誰：** 想了解某支特定 team 的訪客（可能係考慮加入的玩家、對手、scout）。

**用戶想做咩：**
- 了解呢支 team 嘅實力同風格
- 睇 roster，知道有邊啲人
- 睇 match history，了解佢哋最近打緊點

**可用 data：**

```typescript
// useGetTeam(id) → TeamProfile
interface TeamProfile {
  id: number;
  name: string;
  tag: string;
  captainPlayerId: number;    // 可以 link 去 /players/:riotId 但需要先 resolve
  teamElo: number;
  peakElo: number;
  wins: number;
  losses: number;
  isActive: boolean;          // 30 日無比賽就 inactive
  members: TeamMember[];      // 成員列表
  recentMatches: Match[];     // 最近 10 場
  createdAt: string;
}

interface TeamMember {
  id: number;
  teamId: number;
  playerId: number;
  playerRiotId?: string | null;           // 用作 link 去 /players/:riotId
  playerDiscordUsername?: string | null;
  role?: string | null;                    // top/jg/mid/adc/sup/fill，可能 null
  status: string;                          // "active" | "inactive"
  joinedAt: string;                        // ISO date string
}

// useGetTeamEloHistory(id) → EloHistoryEntry[]
interface EloHistoryEntry {
  id: number;
  teamId: number;
  elo: number;      // ELO value at this point
  delta: number;    // change from previous（正係升，負係降）
  matchId?: number | null;  // 係咩 match 觸發，可 link
  reason: string;           // "match" | "season_reset" | "manual_admin"
  createdAt: string;
}
```

**每個 section 嘅資料用途：**

**Team identity（頁頂）：**
- `name`、`tag`：識別 team，tag 係短版 identifier
- `teamElo`：競技水平，最重要指標
- `peakElo`：顯示 team 歷史最高點，代表佢哋最強嗰刻
- `wins`/`losses`：record
- `isActive`：inactive 嘅 team 要讓用戶知道（30 日無比賽），避免誤解

**ELO History Chart：**
- 用 `eloHistory` data，按時間順序顯示 ELO 變化
- 用途：展示 team 嘅成長軌跡同穩定性
- `reason === "season_reset"` 係 season 完結時嘅 soft reset，喺 chart 上可以有視覺標記
- Recharts `AreaChart` — 現有 `PlayerProfile.tsx` 有完整參考實現可以直接借鑑

**Roster：**
- `members[]` — 顯示誰在隊中
- `playerRiotId` 可 link 去 `/players/:riotId`（如有）
- `role` 係用戶自己設定嘅主要位置，可能係 null（bot 加人時未設定）
- `status` 區分 active/inactive 成員，inactive 係長期無出場
- `joinedAt` 顯示成員幾時加入

**Recent Matches：**
- `recentMatches[]` — 近 10 場
- 每場需要顯示：對手係邊個 team、勝負、ELO 變化（這個 team 的）、日期
- 判斷呢個 team 係 A 還是 B：`match.teamAId === team.id`
- ELO delta（這個 team）：
  - 如果係 Team A：`teamAEloAfter - teamAEloBefore`
  - 如果係 Team B：`teamBEloAfter - teamBEloBefore`
- `gameDuration`（milliseconds）可以格式化做 MM:SS 顯示
- `visibleAfter` — 如果係未來時間，呢場 match 係 private，唔應該 link 去 match detail（只顯示結果）

**States 必須 handle：**
- Loading（async data fetch 期間）
- Not found（invalid ID）
- Empty members（新 team 未加人）
- Empty match history（新 team 未打比賽）
- Empty ELO history（新 team 無紀錄）
