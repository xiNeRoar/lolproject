**Issue A — VOD privacy gate (ISSUE-03):**

Title: `[Claude] Frontend: graceful degradation for restricted VODs`

Body content:
```
**Context:** VODs follow match visibility rules (3-layer privacy model). When a VOD's parent match is private/restricted, the API returns 403 or omits the VOD from list results.

**How VOD visibility works (backend):**
- VODs inherit match visibility via `isMatchVisibleTo()` helper
- Scrim matches: only logged-in participants see full stats + VOD
- Tournament/event matches: public by default, captain can override to private
- Captain can set `visibleAfter` date — VOD hidden until that date passes

**What frontend needs to handle:**
1. **VOD list page:** Some VODs may be filtered out server-side. Show "Some VODs are restricted" hint if authenticated user might have access to more
2. **VOD detail page:** If 403 returned, show "This VOD is restricted" message with explanation:
   - "This is a private scrim recording. Only team participants can view it."
   - "This VOD will be available after {visibleAfter date}." (if visibleAfter is in future)
3. **Match detail VOD link:** If match has a VOD but viewer lacks permission, show locked icon instead of play button
4. **No broken states:** Never show an empty video player or loading spinner that never resolves

**Acceptance:**
- [ ] VOD detail page for restricted match shows human-readable restricted message
- [ ] VOD list page does not show blank cards for filtered VODs
- [ ] Match detail page shows locked VOD indicator for restricted matches
- [ ] No console errors or infinite loading states for restricted VODs
```

**Issue B — Profile 403 handling (ISSUE-04):**

Title: `[Claude] Frontend: handle 403 on private player profile sub-routes`

Body content:
```
**Context:** Player profiles have a 3-level privacy setting (public, private, participants-only). When a profile is private, the API returns 403 for all sub-routes.

**Sub-routes that return 403 for private profiles:**
- `GET /api/players/{id}/champions` — 403 `{ error: "Player profile is private" }`
- `GET /api/players/{id}/events` — 403 `{ error: "Player profile is private" }`
- `GET /api/players/{id}/team-stats` — 403 `{ error: "Player profile is private" }`

**Privacy levels (from players.profileVisibility column):**
- `"public"` — anyone can view all sub-routes
- `"private"` — only the player themselves (and admins) can view
- `"participants-only"` — only teammates / match participants can view

**What frontend needs to handle:**
1. **Profile page tabs/sections:** When a 403 is returned for champions, events, or team-stats, show a "This player's profile is private" message in that section (not an error page)
2. **Graceful degradation:** The main profile header (name, avatar) may still load — only sub-data is gated. Show what is available, lock what is not
3. **Participants-only hint:** If viewer is logged in but not a participant, hint that teammates can see more: "Only teammates can view this player's detailed stats"
4. **Own profile:** Never show 403 to the player viewing their own profile (frontend should always pass session auth)

**API response format on 403:**
```json
{ "error": "Player profile is private" }
```

**Acceptance:**
- [ ] Navigating to a private player's profile shows header but locked sub-sections
- [ ] Champions, events, and team-stats tabs show privacy message instead of error
- [ ] Own profile always renders fully (no self-403)
- [ ] No uncaught 403 errors in console
```
