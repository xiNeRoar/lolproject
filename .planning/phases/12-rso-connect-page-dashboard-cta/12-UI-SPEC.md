## Component Inventory

### New Component 1: Connect Page

**Location:** `artifacts/vclol/src/pages/public/Connect.tsx` (new file)

**Route registration:** Add `<Route path="/connect" component={Connect} />` in `App.tsx`, after the `/dashboard` route. Import: `import Connect from "@/pages/public/Connect";`

**Purpose:** Receives `?token=<uuid>` from bot-generated URL. Shows verification prompt. Initiates RSO OAuth via `window.location.href`. Displays error states from `?error=<code>` query params.

**States (3 distinct views):**

1. **Token present, no error** -- Verification prompt with CTA button
2. **Error present** -- Error message with recovery guidance
3. **No token, no error** -- Generic fallback explaining the page purpose

### New Component 2: Dashboard RSO CTA Banner

**Location:** Inline modification within `artifacts/vclol/src/pages/public/PlayerDashboard.tsx`

**Purpose:** Replace the existing yellow warning banner (lines 108-118) with an actionable CTA that links to the website RSO flow (`/api/auth/rso`) via full-page navigation. The existing banner tells users to use `/connect` in Discord -- the new banner adds a direct "Verify with Riot" button for users already logged in via Discord OAuth.

### Dashboard RSO Success Toast

When PlayerDashboard mounts and detects `?rso=success` in the URL:

```
useEffect:
  const params = new URLSearchParams(window.location.search)
  if (params.get("rso") === "success"):
    toast.success("Riot account verified", { description: "Your identity is now confirmed. Welcome to VCLoL." })
    // Clean URL without reload
    window.history.replaceState({}, "", "/dashboard")
    // Invalidate auth cache so hasPuuid updates
    queryClient.invalidateQueries({ queryKey: getGetAuthMeQueryKey() })
```

## Interaction States

### Connect Page

| State | Behavior |
|-------|----------|
| Token present, no error | Show verification prompt with CTA button. Button triggers `window.location.href` navigation (full-page redirect, NOT fetch). |
| Button click | Immediate full-page navigation to `/api/auth/connect/:token`. No loading spinner needed (browser handles redirect chain). |
| Error present | Show error card with appropriate heading/body from error copy table. Always show "Go to Dashboard" link. Show `/connect` Discord hint for `invalid_token`. |
| No token, no error | Show generic page explaining purpose. Link to login page and home. |
| URL parsing | Extract `token` from `?token=<uuid>` and `error` from `?error=<code>` using `URLSearchParams` or `useSearch` from wouter. |

### Dashboard CTA

| State | Behavior |
|-------|----------|
| `hasPuuid === false` AND logged in | Show yellow warning banner with inline "Verify with Riot" button. Button is an `<a>` tag (full-page nav to `/api/auth/rso`). |
| `hasPuuid === true` | Banner not rendered. Existing "Getting Started" checklist step shows as completed (already works via existing logic). |
| `?rso=success` detected | Fire Sonner toast with success message. Clean URL via `history.replaceState`. Invalidate auth query cache. |
| Auth loading | Banner not rendered until `useAuth()` resolves (matches existing pattern). |

## Responsive Behavior

### Connect Page
- `max-w-sm mx-auto px-4` centers and constrains width (matches PlayerLogin exactly).
- Card fills container width. Button is full-width within card.
- No breakpoint-specific overrides needed.

### Dashboard CTA Banner
- `flex items-start gap-3` layout. Warning icon and button shrink-wrap (`flex-shrink-0`). Text block fills remaining space (`flex-1`).
- On narrow screens (<640px), the button may wrap below the text. Add `flex-wrap` to the container and `w-full sm:w-auto` to the button anchor for clean mobile layout.
- This matches the existing banner structure but adds a flex child for the button.
